# حساب‌ها و مجوز واقعی

چهار اسلات اعتبارنامه در خروجی خصوصی این فریمور دیده شدند: حساب اصلی عادی،
SUPER، TEST و SUPPORT. نام‌ها، رمزها و هش‌های واقعی آن‌ها منتشر نمی‌شوند.

در دستگاه آزمایش‌شده، SUPER با `userType=1` و یک درخواست مدیریتی محافظت‌شده
تأیید شد. حساب اصلی عادی، TEST و SUPPORT در ورودهای بررسی‌شده `userType=2`
داشتند و درخواست محافظت‌شدهٔ مدیر برای آن‌ها مجاز نبود. بنابراین نام یک حساب
یا وجود کلمهٔ SUPPORT/TEST به معنی مدیر یا Super Admin اضافی نیست. متادیتای
INIT_PAGE نیز به تنهایی برای اثبات اعتبار نشست کافی نیست.

| قابلیت | نتیجهٔ همین فریمور |
|---|---|
| نام و رمز حساب عادی اصلی | فرمان‌های بومی۹۸/۱۰۲ و ورود تازه تأیید شد |
| رمز SUPER | فرمان۱۰۲ و ورود مدیر محافظت‌شده تأیید شد |
| نام SUPER | فرمان۹۸ رد شد؛ نصب‌کننده اجرا نمی‌کند |
| تغییر TEST/SUPPORT | در این محصول انجام نمی‌شود |
| نام تکراری برای عادی و SUPER | رفتار تأیید نشده؛ Wizard نام متفاوت می‌خواهد |

Wizard از مدیر فعلیِ مجاز، رمز را مخفی دریافت می‌کند، از خروجی تنظیمات بکاپ
می‌گیرد و سپس اطلاعات مطلوب حساب‌های پشتیبانی‌شده را می‌پرسد. هر حساب با ورود
تازه بررسی می‌شود. در پنل، تغییر فقط به حساب همان نشست محدود است. رمزها مشترک
یا ثابت نیستند؛ هر مالک رمز مستقل انتخاب می‌کند. برای نصب جدید رمز بلند و
منحصربه‌فرد انتخاب کنید؛ محدودیت فریمور حداکثر۲۰ نویسه است.

تغییرات PAC آزمایشی و ریست برای فعال‌کردن نام SUPER در محصول عرضه‌شده وجود
ندارد. مسیر واردکردن تنظیمات بومی هم‌زمان نیست و بازخوانی فوری در طول آن می‌تواند
ناپایدار باشد. ابزار نصب برای حساب‌ها صرفاً از فرمان‌های بومیِ تأییدشده استفاده می‌کند.
